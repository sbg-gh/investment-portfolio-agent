## Next implementation slice

M4 is complete. On top of the M1 identity path, the M2/M2a holdings and valuation layers and the M3 proactive machinery it adds an authenticated, READ-ONLY chat boundary with NO schema change (`SCHEMA_VERSION` stays 6; `conversation_id` is an opaque echoed correlation token and the response `request_id` reuses the payload-free `execution_traces.request_id`). A vendor-neutral, stdlib-only `OpenAICompatibleModel` is selected by env var (`MODEL_ENDPOINT`/`MODEL_NAME`/`MODEL_MAX_CONCURRENCY`/`MODEL_CONTEXT_BUDGET`/`MODEL_MAX_OUTPUT_TOKENS`) with conservative Mac-mini defaults; a `BoundedModel` enforces concurrency and output caps; and an injectable `ScriptedModel` keeps the demo, eval suite and tests fully offline. `ChatService.chat` runs through `PortfolioService._run` with a payload-free `chat` trace, authorizes `portfolio_id` before any read, assembles a bounded owner-scoped context, and returns `explanation`, `evidence` (M2a stale/missing/as-of, never fabricated) and validated READ-ONLY `proposed_actions`. THE CENTRAL SECURITY PROPERTY holds: model proposal → deterministic schema validation (`validate_proposal`) → fresh M1 re-authorization → execution, so prompt injection via the user message, context data or a tool result changes what the model says but never what the system does. The seven M4 acceptance behaviors are exercised by the `m4-chat-baseline-v1` eval suite wired into `cli eval` (now five suites), and the guarded `scripts/benchmark_chat.py` records latency/RSS or a clearly-labeled placeholder (Ollama was unreachable at implementation time).

M5a is complete: the memory substrate adds the richer unified-table record contract at schema v7, owner-scoped run capture with deterministic redaction/minimization, scoped keyword retrieval that filters ownership and status/expiry BEFORE ranking, and deletion lineage/expiry. It is SUBSTRATE ONLY and makes no learning/adaptation claim; the sixth deterministic suite `m5a-memory-baseline-v1` (now six suites in `cli eval`) is a scope/capture/retrieval correctness gate kept distinct from any held-out learning evaluation, with no `learning_improvement` key. Embeddings/vectors are deferred and would inherit the same authorization + deletion semantics.

Next is M5b — experience learning: extraction of candidate lessons from runs, the candidate→review→held-out-evaluation→approved→active→deprecated promotion lifecycle, versioned-procedure activation/rollback, retrieval variants and a held-out ablation harness. Adaptation must be proven by a held-out improvement gate with zero privacy regression and a demonstrated rollback — passing deterministic regression fixtures (including M5a's) alone never establishes learning. Before adding any network adapter for chat, add authentication transport, rate limiting, prompt/cache isolation and deployment tests; local services alone do not complete those integration gates.

Keep execution traces and deterministic evaluation fixtures active from M1 onward. M5a adds owner-scoped run records with tool sequences and policy/model versions alongside the payload-free traces; automatic extraction and promotion remain M5b.

## Backlog ordering within M2–M5

First establish instrument identity and reproducible accounting. Then reliable collection and minimal proactive rules. Add model explanations after deterministic outputs are trustworthy. Only then extract experiences and evaluate changed behavior. Keep specialist roles as modules until extra autonomous loops have measurable benefits.

## Definition of done

Code and contracts agree; tests exercise success, denial and retry/failure behavior; no private data or secrets in fixtures/logs; deterministic money math; provenance/freshness visible; local resource impact measured when relevant; documentation clearly distinguishes implemented behavior from planned work. CI must pass on supported macOS/Linux Python versions before release.
