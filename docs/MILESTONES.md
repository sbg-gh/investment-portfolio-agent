Loopback network transport and interactive login are delivered by M7 slice 7a (TLS, remote deployment and prompt/cache integration remain open); M2a fixture-backed valuation is implemented; M2 is complete (import provenance, the transaction ledger with reconciliation, deterministic baseline coverage and the enhanced-monitoring admission machine); M3 is now complete (durable jobs/leases, a persisted outbox with deduplication, per-user preferences, deterministic monitoring and crash/resume semantics); M4 is now complete (authenticated offline chat over the common services, a bounded vendor-neutral local-model adapter, evidence rendering and READ-ONLY specialist tools behind a deterministic schema+authorization gate); M5 is now SPLIT — **M5a (memory substrate) is delivered** as substrate only (richer record contract at schema v7, owner-scoped redacted run capture, scoped keyword retrieval, deletion lineage) and makes NO learning/adaptation claim, while **M5b (extraction, promotion/rollback and the held-out ablation apparatus) is delivered** at schema v8 with the pre-registered analysis yielding `significant_improvement` on the synthetic scripted simulation ONLY; **M6 (paper portfolio simulation) is delivered** at schema v9 as a deterministic simulation with no live mode. M0-M6 are delivered. M7 slice 7a (local web UI) is delivered; slice 7b is planned. See the end of the next-slice notes for what remains outside the plan.

## Next implementation slice

M4 is complete. On top of the M1 identity path, the M2/M2a holdings and valuation layers and the M3 proactive machinery it adds an authenticated, READ-ONLY chat boundary with NO schema change (`SCHEMA_VERSION` stays 6; `conversation_id` is an opaque echoed correlation token and the response `request_id` reuses the payload-free `execution_traces.request_id`). A vendor-neutral, stdlib-only `OpenAICompatibleModel` is selected by env var (`MODEL_ENDPOINT`/`MODEL_NAME`/`MODEL_MAX_CONCURRENCY`/`MODEL_CONTEXT_BUDGET`/`MODEL_MAX_OUTPUT_TOKENS`) with conservative Mac-mini defaults; a `BoundedModel` enforces concurrency and output caps; and an injectable `ScriptedModel` keeps the demo, eval suite and tests fully offline. `ChatService.chat` runs through `PortfolioService._run` with a payload-free `chat` trace, authorizes `portfolio_id` before any read, assembles a bounded owner-scoped context, and returns `explanation`, `evidence` (M2a stale/missing/as-of, never fabricated) and validated READ-ONLY `proposed_actions`. THE CENTRAL SECURITY PROPERTY holds: model proposal → deterministic schema validation (`validate_proposal`) → fresh M1 re-authorization → execution, so prompt injection via the user message, context data or a tool result changes what the model says but never what the system does. The seven M4 acceptance behaviors are exercised by the `m4-chat-baseline-v1` eval suite wired into `cli eval` (now five suites), and the guarded `scripts/benchmark_chat.py` records latency/RSS or a clearly-labeled placeholder (Ollama was unreachable at implementation time).

M5a is complete: the memory substrate adds the richer unified-table record contract at schema v7, owner-scoped run capture with deterministic redaction/minimization, scoped keyword retrieval that filters ownership and status/expiry BEFORE ranking, and deletion lineage/expiry. It is SUBSTRATE ONLY and makes no learning/adaptation claim; the sixth deterministic suite `m5a-memory-baseline-v1` (now six suites in `cli eval`) is a scope/capture/retrieval correctness gate kept distinct from any held-out learning evaluation, with no `learning_improvement` key. Embeddings/vectors are deferred and would inherit the same authorization + deletion semantics.

M5b is complete as an APPARATUS: deterministic extraction, the promotion lifecycle, versioned procedures with rollback and the held-out ablation harness (seventh suite `m5b-learning-baseline-v1`, now seven suites in `cli eval`, see M5b.md). The M5 held-out gate is MET on the synthetic scripted simulation only: the pre-registered analysis returned `significant_improvement` (b=32, c=0, interval [0.8911, 1.0]), which is the ceiling outcome of that design because the scripted model follows the approved-procedure channel by construction. It is not evidence that a real LLM adapts; that needs held-out logged real-model behaviour, an effect not guaranteed by construction and a larger independent held-out set. Passing deterministic regression fixtures (including M5a's) alone never establishes learning. Before adding any network adapter for chat, add authentication transport, rate limiting, prompt/cache isolation and deployment tests; local services alone do not complete those integration gates.

M6 is complete. Schema v9 adds paper-only tables (`paper_accounts`, `paper_ledger`) whose foreign keys reach only users, portfolios, securities, market observations and paper accounts, so a paper fill cannot touch real holdings; this is proven by byte-identical dumps and an SQLite-authorizer test, not only asserted. The eighth deterministic suite `m6-paper-baseline-v1` (now eight suites in `cli eval`, see M6.md) is a correctness gate with no performance, learning or return claim. Corporate actions are explicitly deferred.
M7 slice 7a is done: an optional loopback web UI (docs/UI.md) with token login and in-memory sessions, portfolios, holdings import/remove with receipts and idempotency keys, a valuation dashboard that withholds the total on stale or missing lines, chat over staged SSE with evidence and a deterministic-facts fallback, a minimal operator area (register instrument, enter price/NAV observations) and the ninth eval suite `m7-web-security-baseline-v1`. A starter-data follow-up to 7a adds operator-attested registration of the 20 `ai-conviction` symbols and a synthetic sample portfolio (command and buttons, no seeded prices; docs/UI.md). M7 slice 7b is planned and not implemented: alerts (outbox and preferences), the paper account screens, operator CSV ingest, membership/monitoring admin, the dead-job review queue, "enqueue + tick now", and memory/procedure review and publish.

Overall plan status: M0-M6 and M7 slice 7a are delivered. Outside the plan and still open: a real market-data adapter with its licensing review, production tick scheduling (the stated cadence is a twice-hourly refresh of all portfolio symbols), real-LLM evidence (a single recorded llama3.2:3b smoke run parsed but gave wrong figures; see docs/UI.md), corporate actions, M7 slice 7b, tax-lot optimization/reporting, embeddings, TLS/remote deployment and moving the frontend toolchain to Node 22 LTS.
Keep execution traces and deterministic evaluation fixtures active from M1 onward. M5a adds owner-scoped run records with tool sequences and policy/model versions alongside the payload-free traces; M5b adds deterministic extraction and gated promotion on top of them.

## Backlog ordering within M2–M5

First establish instrument identity and reproducible accounting. Then reliable collection and minimal proactive rules. Add model explanations after deterministic outputs are trustworthy. Only then extract experiences and evaluate changed behavior. Keep specialist roles as modules until extra autonomous loops have measurable benefits.

## Definition of done

Code and contracts agree; tests exercise success, denial and retry/failure behavior; no private data or secrets in fixtures/logs; deterministic money math; provenance/freshness visible; local resource impact measured when relevant; documentation clearly distinguishes implemented behavior from planned work. CI must pass on supported macOS/Linux Python versions before release.
