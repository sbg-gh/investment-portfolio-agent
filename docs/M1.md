# M1 local identity and persistence implementation

## Trust boundary

`Store` is the internal persistence layer, retained for offline administration and M0 compatibility. New application callers use `PortfolioService` with a context returned by `Authenticator.authenticate(token)`. They cannot pass an owner ID to portfolio or memory methods. OperatorService requires an operator credential for public facts and global membership. Possession of a user credential permits that user's operations; operator status does not bypass portfolio ownership.

Tokens are cryptographically random and stored only as SHA-256 digests. Provisioning returns a token once. Tokens default to 24-hour validity; contexts expire after five minutes or at credential expiry, whichever is sooner. Every operation checks signature, expiry and current credential revocation. Signing keys are process-local; restarting invalidates contexts but existing unrevoked credentials can authenticate again. No HTTP transport is included. Transport authentication, TLS, rate limiting and interactive login remain requirements before remote access.

The provision/revoke methods are trusted local administration, never exposed as user tools. OS access to the database or process can bypass application controls. Use protected storage. Operator public ingestion still requires an independently public source; it is not an automatic privacy classifier.

## Local composition example

```python
from portfolio_agent.auth import Authenticator
from portfolio_agent.core import Store, FixtureValidator
from portfolio_agent.services import PortfolioService

store = Store()  # in-memory; use a protected local path for persistence
try:
    store.create_user('alice')  # trusted bootstrap only
    auth = Authenticator(store)
    token = auth.provision('alice')  # return through a secure channel; do not log
    context = auth.authenticate(token)
    app = PortfolioService(store, auth, FixtureValidator({}))
    portfolio = app.create_portfolio(context, 'Personal')
    assert app.holdings(context, portfolio) == []
    auth.revoke(context.credential_id)
finally:
    store.close()
```

## Schema upgrades

`PRAGMA user_version` tracks migrations: v1 establishes the legacy schema; v2 adds explicit memory scope, quarantined legacy records, credentials and execution traces. A fresh database ends at v2. An unversioned M0 database upgrades atomically under an immediate transaction. Failed DDL/data changes roll back with the version. Future schema versions are rejected.

All legacy memories with NULL owners move to `memory_quarantine`, including legitimate old public facts. M0 did not preserve enough information to prove their public origin. Private retrieval cannot access quarantine. A trusted operator must independently verify a public source and re-ingest a fact; there is deliberately no automatic release operation. Private records retain ownership and content.

Back up an existing database before opening it with new code. For an unversioned M0 file, use the standard SQLite backup API from the old version or an administrative tool. The new backup helper accepts only current-schema databases; it does not silently upgrade archives.

## Backup and recovery

`backup(store, new_path)` uses SQLite's backup API. `restore(snapshot_path, new_path)` opens the source read-only. Neither overwrites a file. Integrity, foreign-key and exact schema checks must pass; backup files are created with owner-only permissions. Finish active transactions before backing up. Restore preserves scoped data and traces, but revokes every credential so recovery cannot resurrect old access. Re-provision users through trusted administration after recovery.

## Execution traces

Each application operation records a generated ID, authenticated user, request ID, fixed operation name, outcome, policy version and elapsed milliseconds. No symbols, holdings, portfolio names, memory bodies, source text, tokens or exception messages are recorded. Retrieval is user-scoped. Invalid signatures do not create traces attributed to the claimed victim. Operational counters for unauthenticated attempts remain transport work.

A successful mutation and its trace share one transaction. A failed action rolls back to a savepoint; a denial/error outcome may then commit independently of that rolled-back action. If trace persistence fails, the outer transaction rolls back successful mutations too. Private trace retrieval does not recursively trace itself.

These traces are an early evaluation substrate. They lack the tool sequences, model versions, evidence lineage and user feedback needed for later experience extraction; add those deliberately with payload minimization in M2–M5.
